# Cooperative startup candidate evaluation

ED-29's candidate cycle now composes the existing scratch planner, completed-evidence catalog and shared alternative comparator. It introduces no persistent namespace, stock owner or game action. The producer supplies a current comparable candidate set, explicit return policy/order, and per-call frame/candidate limits. Actual source discovery, native quote/proposal generation, policy configuration and default runtime adoption remain separate unfinished work.

A call snapshots the supplied project inputs, policy and limits before admission callbacks can alter them. It resumes the first missing candidate through the existing planner, captures completed evidence, and proceeds in supplied order. Total newly simulated frames across all candidates never exceeds the single frame limit (0..10001); processed candidate attempts cannot exceed the candidate limit (0..16). Cached completed candidates consume neither budget. The catalog's all-requested-candidates rule still prevents partial comparison from granting a winner.

A partial job is retained by the existing planner. Reset requires no new cursor: the catalog identifies already completed candidates and the scratch job identifies current progress. If a guard expires after the forecast finishes but before capture, the completed scratch result remains available for capture on a later call with zero new simulation frames. Catalog capacity refusal is propagated and preserves existing entries. Expired observations, stale clocks and conflicts remain deferred under the existing owners. A different candidate set or changed input cannot reuse mismatched saved evidence.

The frame budget measures simulator work only. Input snapshotting, lookup, state validation, serialization/publication and comparison have their own cost; callers must reserve CPU for them. The callback guards frame admission and between-candidate work, not an absolute CPU guarantee or transactional rollback of already completed frames. Per-home/aggregate Memory and CPU pressure still require ED-43 qualification.

Final native birth admission remains a separate read-only current-world check. A completed forecast/choice is not a lease, birth authorization, capital reservation or confirmed income. Withdrawal or rollback must reconcile real work under actual spawn/logistics/task/journal/claim owners. No additional namespace migration is required by this cycle.

# Remote birth policy integration

ED-29 increment: an explicit optional RemoteFleetBirthPolicy is shared by ordinary recruitment and final spawn admission through createNativeBot. prepare can perform guarded planning; current must only read the current selection. Undefined preserves ordinary allocation, null defers new births, and a placement binds the request to one spawn and exit. Population demand copies and validates that placement before publication. Recruitment replaces queued requests when body or placement changes and preserves already-paid incubation during planning deferral.

The default entry point uses no injected policy. This introduces no production planning namespace or memory migration. The selected native scenario supplies a fixture policy which completes five real static travel legs in batches of two before publishing selected geometry. Fixture selection survives global reloads. It exercises ordinary scouting, management, recruitment and dispatch; it is not an autonomous profitability selector, a forecast calibration, or a production persisted-plan implementation.

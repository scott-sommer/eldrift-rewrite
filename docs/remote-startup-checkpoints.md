# Resumable forward project checkpoints

ED-29 adds a JSON wire format to the existing forward project simulator. `project.checkpoint()` captures a detached frame-boundary snapshot; `restoreStartupProject(originalInput, checkpoint)` validates and restores it directly. The caller still chooses a maximum frame count and guard for each subsequent advance. Restoring executes no allocation, mining or elapsed simulation frames.

Format1 stores the frame cursor, physical spawn slots/funding, accepted receipt identities, pending delivery settlements, construction/source state, finite couriers, container durability/repair/decay, accepting sink and both streaming cash ledgers. Retired couriers encode their infinite next-action sentinel as null and reconstruct it explicitly. Worker waves and the previous miner are rebuilt from the bounded birth schedule rather than stored twice. All results and checkpoints detach nested state; completed result reads no longer mutate simulator state.

The exact input binding normalizes object property order, live-name Set insertion order and optional defaults. Original stock, body order, schedule, policy, service durations, reservation-independent source capacity and all other model inputs remain fenced. A changed candidate must start a fresh projection. This does not prove that an old observation remains current at native commit.

Each component validates its own restored state. Project validation additionally checks frame agreement, chronological and unique settlement identities, birth schedules and placement, ledger agreement, source/harvest/cargo/construction/repair/loss conservation, sink acceptance and container timing. Pending receipts are distinct from settled credits; neither a reset nor an earlier emitted late receipt can fund a past birth. Outside income remains excluded from source-only recovery accounting. These are schema and invariant checks, not a cryptographic authenticity guarantee.

The wire retains bounded receipt history for output equality and duplicate-settlement protection. It is not constant-space accounting storage: checkpoint cost grows with retained events. Export/restore reject above1,048,576 JSON characters, input identity262,144 characters or the shared copier's100,000-node/depth100 limits. The model retains its existing event/input bounds. The synchronous forecast/result API does not acquire the checkpoint size limit. A future live planning owner must handle capacity refusal explicitly and qualify serialization CPU and total memory pressure before adopting this wire. No new production Memory namespace or migration is introduced here.

The existing safe JSON copy/parser now lives in core, with the persistence import path re-exporting the same implementation. This lets the portable simulator reuse its finite-value, cycle/prototype, property and budget checks without depending on persistence.

Fourteen checkpoint cases verify every frame of a short construction/mining/delivery project; repeated resets across a1,700-frame project and retired couriers; pending settlement; input invalidation; detached outputs; property/default normalization; invalid format/clocks/stock/ledgers/identities; no replay; destroyed infrastructure; blocked sinks; outside income; conservation and settlement ordering.

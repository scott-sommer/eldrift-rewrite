# Durable startup candidate evidence

ED-29 now retains completed assessments separately from its one per-home scratch simulation. `remoteStartupCandidates/<home>` is version1, owner `remotes`. At most16 uniquely named entries retain exact planning context, canonical input identity, canonical return-policy identity, captured tick and detached assessment. Each input identity is limited to262144 string characters; the complete catalog is limited to1048576 JSON characters. These are refusal limits, not a claim that the maximum is affordable within shared Screeps Memory. Aggregate homes, serialization cost and CPU admission still require ED-43 qualification. This consumer is not registered by the default bot.

The catalog captures only the actual completed result from the existing planning owner. Incomplete, absent, changed or expired forecasts cannot initialize it. Each capture uses a caller-supplied revision and monotonic clock; a stale writer is refused after result lookup as well as before it. A new entry replaces only its own ID and reclaims expired evidence. Capacity refusal preserves all existing entries. Scoped withdrawal removes evidence, never a planning job or another feature's state.

Lookup is read-only and requires a freshly reconstructed complete query: same room/source/generation/binding/observation/expiry, exact canonical project input and same return policy. Lookup cannot travel backwards behind the catalog clock or capture tick. The caller still owns producing current facts and binding; replaying an old query is not current world revalidation. Returned data is detached.

Comparison requires a complete set of up to16 distinct requested IDs at the same current tick and horizon. Any missing/stale candidate defers the entire comparison with its identity; completed candidates do not win by default while another candidate is pending. All complete assessments, including rejected ones, are retained in the comparison. The shared portable final-return/payback ordering chooses a single mutually exclusive alternative, with deterministic identity ties. Different alternative inputs must still describe a comparable world/budget baseline. No concurrent portfolio cash is synthesized by summing independent household forecasts.

Sequential completed jobs may now be captured before the next scratch job replaces them, and their read-only choice survives JSON/global reset. There is no automatic candidate-generation loop, geometry publication, birth admission, execution lease or capital reservation here. Automatic configuration/adoption and full native lifecycle/economic calibration remain open.

Rollback: disable the candidate consumer before removing this evidence-only namespace or running an older version. No migration from another namespace is invented; foreign/future/corrupt envelopes fail closed. Discarding evidence must never discard admitted spawn/logistics/tasks/journals/claims or confirmed receipts. If an eventual consumer has issued real work, settle or reconcile those authoritative owners independently. ED-44 must rehearse this boundary; adding these instructions is not a completed rollback rehearsal.

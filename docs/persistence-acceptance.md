# ED-16 persistence foundation acceptance

- Schemas and ownership: colony, tasks v2, missions, intel, plans, operator overrides, reservations and creep identity roster use owned versioned envelopes and JSON-only data. Schema tests cover valid/invalid records; versioned-state/save-state tests reject wrong owners, corrupt data and future versions without mutation.
- Migration/reset: persistent-batch and migration-gate tests cover bounded manifests, resume after JSON reconstruction, idempotence, changed-manifest rejection, failed records and failure between record write and checkpoint. task-runner and persistent-configuration tests reconstruct handlers/providers after reset. The actual-engine reload scenario proves module reconstruction and persisted configuration. Legacy import is not yet implemented.
- Cache/namespace isolation: the bounded cache is reconstructible and has no StatePort, so eviction has no persistent deletion authority. Intel tests prove loss of vision preserves IDs/freshness and unrelated state; older observations cannot replace newer intelligence.
- Lifecycle: unit-lifecycle tests cover actual queued-task/claim release, replacement object IDs, bounded progress and interrupted checkpoints. The production actual-engine retirement case proves local departure cleanup. cancel-task, mission cancellation and colony transfer tests prove release of the owned scope while preserving other claims. These are foundation APIs; the respective future gameplay features still must invoke them through their lifecycle decisions.
- Diagnostics/policy: memory-capacity.md and evidence/memory-profile.json record reproducible synthetic schema-valid size/serialization measurements at 1/5/20 rooms. legacy-memory-compatibility.md specifies selective mappings, preserved source data, dry runs, bounded conversion and rollback requirements. RawMemory segments remain deferred until measured need.

Current validation: quality/Lizard passed with 58 production files and zero violations; full suite 175 tests passed in 2.40s. Latest unchanged production engine suite passed 11 checks in 9.58s in the lifecycle milestone. Capacity runner independently checks byte counts, schema construction and non-mutation.

This completes the persistence foundation scope. It does not close feature parity, production task registration, power-creep or cross-shard transfer lifecycle, complete migration/rollback, engine performance budgets, or soak gates. Those remain required under the execution/feature issues and ED-42 through ED-44. No production deployment has occurred.

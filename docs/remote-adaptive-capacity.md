# Adaptive remote source capacity

ED-29 remains In Progress. The policy, bounded observation store and native runtime integration are implemented. Activation is per home through `remoteAdaptiveEnabled`, default false. This does not complete reachability parity or the wider ED-29 operating envelope. Four development native cases pass; clean-commit qualification is the next check, and archived evidence will be recorded separately.

## Responsibilities

`features/population/spawn-load` owns trailing spawn occupancy history, independent from remote strategy. `features/remotes/capacity` owns the supported source count, evaluation clock and last evaluated load. `portfolio` enforces an optional `maximumSources` independently from slots, haulers, spawn throughput and total workforce. Two source miners plus a one-slot room commitment therefore require two supported sources and three workforce slots. Atomic rooms still cannot fragment to fit a reduced source budget.

A history sample is a half-open one-tick observation. Adjacent identical samples merge into one segment. Trimming keeps at most 1,500 segments; the worst case alternates every tick. Observation gaps remain gaps. Detached reads and persisted validation prevent mutation through snapshots, overlapping history, wrong owners, unknown future schemas and corrupt records. Duplicate or backwards samples do not rewrite history. Capacity saves require a current revision and non-regressing clock.

## Ported decisions and deliberate corrections

The legacy reference and exact source locations are in remote-adaptive-porting-audit.md. Evaluation initializes three sources and an evaluation timestamp, then waits a configured interval (the default is 1,500 ticks). At full observation coverage, load <= .75 adds one; load >= .90 removes one; the interior band holds. Capacity has a zero floor and an explicit configurable maximum bounded by the portfolio inventory limit of 128. Missing observations or no current physical spawn hold an established allowance. Controller levels below three expose two sources; level three exposes three while its stored adaptive value can evolve; level four and above expose the stored value. This preserves the legacy distinction between the getter and evaluator.

Unlike additive legacy duration events, the observation model cannot count a single spawn as both occupied and starved in the same tick. It divides occupied plus energy-starved spawn ticks by 1,500 times current spawn count, preserving the legacy denominator, and clamps to one after capacity loss. This corrects overlapping event accounting. No claim of equivalent measured values is made before native qualification.

## Native integration contract

Main registers an owned urgent evaluator separately from optional background discovery. At tick T evaluate the closed window ending T-1, then record T after dispatch. First evaluation at tick one and first adjustment at tick 1,501 should therefore use exactly 1,500 observations. Resolve settings per home; default-off homes must not open these new state namespaces. Decorate the management portfolio source cap without replacing existing slot or workforce limits.

The observer must combine actual active spawn occupancy with dispatch reservations after flushing effects. Count ready, affordable-at-full-room-capacity demand that the allocator skips for insufficient available energy. Measuring only native ERR_NOT_ENOUGH_ENERGY would miss that demand. Use the existing same-tick energy ledger and do not call stateful final admission twice. Exclude born names, expired/not-yet-ready requests and impossible bodies. Document the treatment of cancellations and uncertain native effects. Isolate observation failures per home and refuse corrupt history rather than silently resetting it.

Packaged cases `--remote-capacity-idle` and `--remote-capacity-starved` each run 1,505 ticks. The busy and off cases run 30 ticks. They use ordinary main with initial room funding, one canonical queued demand where appropriate, and code reloads. The harness does not patch energy or lifetime mid-run, seed observation histories, or directly invoke the evaluator. Development runs show the idle allowance rising 3 to 4 and starved allowance falling 3 to 2 at tick 1,501, with no earlier change. The starved case makes zero native spawn calls. A funded four-part birth yields exactly twelve occupied observations and no starvation. Off mode leaves both new namespaces absent. Clean-commit runs and regression evidence are still required before archiving qualification. Full-life reachability feedback is a separate remaining port: actual source arrival or a never-arrived miner's final lifetime tick, with two consecutive failures scoped to one home. Generic route or combat failures do not establish that evidence.

## Validation

Focused tests cover interval and threshold boundaries, level-specific getters, missing observations, zero physical capacity, floor/ceiling, bounded history, current-capacity normalization, duplicate sampling, detached state, reloads, corrupt history, revision/clock fencing, and source versus room/workforce budgets. Runtime tests additionally cover disabled background scheduling, closed-window evaluation, per-home override precedence, post-dispatch energy and structure reservations, read-only queue demand and reported corrupt history. Full unit suite: 1,504 tests / 403 files in 10.56s. Type checking, lint, boundaries, packaged bundle and Lizard pass: 723 production / 594 test files, zero violations. Four development native cases passed with a dirty worktree; these are diagnostic evidence pending clean-commit runs.

## Configuration

`remoteAdaptiveInitialSources` defaults to 3, `remoteAdaptiveMaximumSources` to 128 (both bounded 0..128); the initial value clamps to the maximum. `remoteAdaptiveInterval` defaults to 1,500, bounded 1..1,000,000 ticks. A shorter interval still requires a full 1,500 observed ticks before adjusting. `remoteAdaptiveIncreaseAt` and `remoteAdaptiveDecreaseAt` default to .75 and .90, bounded 0..1 with increase strictly below decrease. These controls use ordinary configuration precedence and per-home overrides. They do not supersede existing workforce or economic admission budgets. Disabling adaptation retains history without updating it; gaps hold future adjustments until a complete current window is available.

ED-29 remains In Progress. Completed accepted startup forecasts can now be retained independently of the replaceable scratch planning job. The remotes feature owns capture, exact query lookup and explicit generation-scoped withdrawal. Final admission and cohort maintenance accept an injected result reader; their default scratch reader remains compatible.

## Ownership and validation

The new namespace remoteStartupApprovals/<home> belongs to remotes, version 1. It retains the canonical planning input and completed project checkpoint, geometry-only travel quote, room list and original return policy. It never trusts a bare acceptance flag: validation restores the completed checkpoint without advancing simulated frames and reassesses acceptance. Participant identities, bodies, home/source, spawn/exit, conservative travel and retirement clocks must agree with the quote. Boosted participants are unsupported and refused. Native world observations are not serialized into this record.

There is at most one approval per room/source, at most 16 approvals and at most 262144 JSON characters in each home data record. Capacity refusal preserves prior approvals. Capture uses optimistic revision and monotonic clock checks. Reads do not initialize missing state. Replacement affects only the same room/source; expiry is checked on lookup, and expired records require explicit withdrawal rather than silently evicting another source. The native single-entry envelope serializes to 23770 ASCII JSON characters; this is a bounded fixture measurement, not a CPU or colony-scale Memory qualification.

An approval is evidence rather than spending authority. Execution must still supply the current configuration/topology binding, exact scheduled birth slot, current lease/profile, original policy and observed prior paid births. Changed context, expiry or missing evidence refuses admission. Withdrawal removes only the selected room/source/generation and neither cancels queued work nor retracts issued native actions; the existing cohort cleanup owner handles unstarted requests.

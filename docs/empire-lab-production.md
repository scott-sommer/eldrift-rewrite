# Empire lab-production allocation foundation (ED-36)

Legacy resourceManager.js at baseline f2bbf7e8 selects a deficient global stock target, expands missing intermediates and distributes recipes across lab rooms. Its setupLabs155+ round-robins the resulting compound list without proving room-local stock or coordinating outstanding final-product windows. The rewrite currently executes configured local production chains; this increment supplies the portable allocation boundary needed for empire coordination.

`planEmpireProduction` receives explicit global observed stock, ordered priority targets, up to50 distinct eligible room snapshots with disjoint local inventories/options, up to50 outstanding final-product commitments (at most one per room), an injected recipe lookup and a shared bounded node budget. It returns at most one proposed assignment per uncommitted room: home, final product, funded final amount and first dependency step.

Observed global product and outstanding committed windows reduce each shared target once. Stable room-name order and product tie-breaking make plans reproducible under room enumeration changes. Local ProductionDependencies proves that a complete final window is fundable, shrinking scarce windows with the existing bounded halving policy. It reports the funded final quantity separately from the first intermediate step; these quantities differ when preserving intermediate floors. A room cannot borrow raw stock from a remote warehouse just because global totals show it. Local floors, reserve gaps and excluded/claimed availability remain represented by its injected inventory. Global observed product must include eligible local product rather than silently undercounting it.

This is deterministic feasible allocation, not an optimal throughput/transport-cost solver. It does not execute native effects or promise intermediate transport. One room's proposed final window reduces the remaining global deficit even if its first step is an intermediate, preventing another room from receiving the same final demand in the same plan. Existing commitments occupy their room and count toward demand. Invalid scopes/recipes/stock or exhausted shared/per-room planning budgets throw before a result is returned; inputs remain unchanged. The existing per-room planProduction API preserves its return contract and now delegates to a funded-batch result used by the allocator.

## Integration still required

This foundation is not registered in the ordinary bot and does not establish empire-production parity. The next implementation must persist feature-owned commitments and their immutable contexts; derive observed global and disjoint local inventory with boost/manual exclusions; reconcile existing commitments before considering new demand; retain/retire windows through admitted lab hauling and maintenance; and drive normal lab assignment/production without writing operator configuration every tick. Local policy must remain selectable. Configuration must define target ownership, participating rooms and enablement explicitly, and handle inconsistent room policies without ambiguous grouping. No global stock estimate may fund effects unavailable to the local room; ED-37 owns eventual terminal movement.

A subsequent real-engine qualification should use two rooms with a shared target smaller than two local batches, verify that total final production stays within the shared target across resets, complete intermediate chains locally, preserve boosted-role exclusions, replace/retire commitments on policy changes or actual room loss, and finish ordinary hauling/receipts without stranded cargo. Visibility loss must retain state and avoid false completion. Include short stock and lower-priority feasibility, pre-existing commitments, migration and rollback evidence. Until that runs, only portable unit/contract behavior is claimed.

No configuration key, native scheduling path, console API or memory schema is added by this foundation. The full rewrite, ED-36 and empire integration remain incomplete.

## Durable window store checkpoint

`features/industry/empire-production` now supplies the owner-controlled durable store needed by the forthcoming coordinator. It is not yet composed into ordinary runtime. Namespace industry-empire-production/empire, owner industry, schema1 holds at most50windows and one per home. Each window preserves original home/product/amount/context, absolute original root ceiling and initial dependency step for replay identity. A replay cannot overwrite a progressed or retiring window with a new policy. Bulk admission builds and validates the full candidate state before one write; absent reads and empty admission do not initialize state. Callers must use a new admission after old work is released, rather than treating replay as a policy update.

Observed positive room-total final-stock deltas reduce the outstanding amount; negative deltas never increase it. Repeated observations are idempotent. Observations are stock fulfillment, not manufactured-success counters: imports can satisfy a window, while global observed stock must still determine whether more empire demand exists. Room-total snapshots must include the same owned banks/labs/admitted courier pools across internal transfers, or a transfer could look like new stock. Terminal coordination must reconcile its actual transfers with that accounting boundary before enabling imports/exports. Completed intermediate stages replan locally toward the fixed remaining window; a temporarily unfundable next stage is null/blocked and retries on a later observation. Partial final progress shrinks execution ceilings so later consumption cannot resurrect already credited work.

Completed windows enter retiring; explicit cancellation also retires a window while retaining its remaining demand. A retiring window cannot advance. Release requires an injected settlement predicate to affirm the lab owner's admitted work has settled. The store never clears assignments, tasks, claims, receipts or operator configuration. Missing observations do not delete windows or imply completion; visibility-loss behavior still requires native qualification. Global target reductions, target removal, participant loss and policy-context changes must explicitly retire affected windows in the coordinator before replacement. Retiring windows still occupy their room; outstanding demand must be reconciled conservatively until physical effects settle.

## Responsibilities

RemoteFleetBirthPolicy now has an optional read-only service selection alongside birth placement. Undefined preserves ordinary geometry; null withdraws productive work. A supplied plan must match the current profile home/source/room/body and pass the existing travel-plan geometry validation. The actor receives a detached copy. Assignment generation, lease expiry, current safety, health and TTL remain independently enforced; a geometry selection is not permission to mine or spend capital.

Mining acquires the selected tile through the common station reservation owner and uses that exact station during approach/extraction. An unavailable selected tile does not fall back to a different tile. Courier service selects only the container at the selected station and the selected owned sink. Each trip carries the existing LogisticsRequest.service collection/deposit/avoid contract. Shared hauling/transfer code enforces exact service positions and excludes the miner station from pathing. Changed request geometry or sink invalidates productive authority; ordinary return/banking remains the separate cargo-preservation policy.

No task or logistics schema changes were needed: exact logistics service contracts already existed. Default policies remain available. The selected policy provider owns fresh binding/generation lookup; the native fixture stores one source plan derived from visible geometry and rechecks profile generation/body. This is not automatic economic selection or a full route/fact quote.

# Persistence implementation contract

State records use an owner/version/data envelope. Opening validates ownership and future versions, migrates an isolated snapshot and commits only validated plain data. Explicit saves require an initialized current-version record. Caller mutations do not persist automatically. Memory.eldrift format 1 is isolated from legacy keys; unknown/corrupt roots are preserved and rejected.

Migration batches checkpoint after each successful record and stop at a record cap or injected CPU admission boundary. Failure leaves the cursor on the failed record. A reset after a record write but before its checkpoint can replay that record, so record migration must be idempotent. Plan IDs must identify an immutable ordered key manifest; callers must not reuse an ID with changed ordering. Per-record migrations are synchronous and must themselves remain bounded. runPersistentMigration supplies versioned Memory-backed checkpoints and stores the exact ordered manifest, rejecting changes under the same plan ID. Production tick admission now supplies an explicit migration registry; later sections record the integration evidence.

Intel state records lastSeen and IDs. Unseen rooms retain prior intelligence; a later explicit observation can replace stale object lists. Freshness is computed from lastSeen. Reconstruction after JSON serialization preserves data and leaves unrelated plan/legacy namespaces alone.

Colony, task, mission, plan, operator, intel and reservation schemas now exist alongside bounded caches and serialization diagnostics. Production lifecycle/migration admission and synthetic capacity measurements are implemented below; feature-specific integrations and live-empire measurements remain later capability/release work. No legacy memory is automatically imported. Import compatibility and rollback must be rehearsed under ED-44 before release; RawMemory segments remain deferred until measured need.

Exclusive reservation schema/store now tracks resource key, holder, lifecycle scope and expiry. Contending holders/scopes are rejected; same-holder renewals are allowed. releaseHolder supports confirmed death/cancellation, releaseScope supports mission cancellation or colony ownership transfer, and expiry uses an exact tick boundary. Callers must supply confirmed lifecycle events; absence from room vision is not death. This is an exclusive-slot primitive, not a quantity reservation ledger. Runtime cleanup wiring and resource-quantity reservations remain capability work. Persistence/smoke 28 tests pass in 276ms; quality passes.

measureSerialization reports JSON UTF-16 code units and UTF-8 bytes separately, plus elapsed time in the injected clock's units. Timing includes plain-data validation/copy and final serialization; it is not a claim about engine Memory serialization CPU. Run on demand or staggered, not automatically each tick. RawMemory segment decisions must use representative state measurements plus engine evidence. Unicode accounting and non-mutation tests pass; latest persistence/smoke 30 tests passed in 262ms and quality passed. Production telemetry wiring and representative size reports remain pending.

Production main now loads operator/config through the isolated Memory adapter. The app-level provider validates and caches one snapshot per tick, preserving shared and room precedence. Saved configuration changes take effect next tick; rebuilding the provider after a serialization reset recovers the same values. Empty state initializes an empty operator config (defaults), without touching legacy namespaces. Corrupt configuration is rejected and reported by the outer loop rather than silently replaced. Confirmed unit retirement clears its task queue and releases only that holder's claims. Cleanup is replayable across resets. The caller must supply confirmed retirement; absence from a visible-room observation is deliberately insufficient. Live unit lifecycle wiring remains part of the execution framework integration.

Persistence validation rejects sparse arrays even when an extra named property masks the missing index count, avoiding silent JSON data loss.

## Owned-creep lifecycle integration

Production admission now reconciles a persistent units/creeps roster of names and object IDs against Game.creeps, after migrations and claim expiry. Game.creeps is the complete owned-creep collection, unlike visible-room object queries (https://docs.screeps.com/api/#Game.creeps). Spawning creeps are included; room observation changes cannot trigger retirement. The adapter deliberately excludes power creeps, whose unspawned lifecycle differs.

Absence means retirement from this shard, not proof of death on every shard: legacy formations.js includes portal travel. Retirement clears local tasks and holder claims only, leaving mission/intel/plan and legacy state untouched. Cross-shard handoff must capture its transferable state before departure when mission support is ported; this does not implement that transport. Name reuse with a different object ID retires the old identity before normal gameplay is admitted.

At most 20 retirements execute per admission. Each successful cleanup checkpoints the roster; interrupted writes replay idempotent task/claim cleanup. Remaining backlog blocks gameplay until reconciled. Observation or persisted schema corruption rejects admission without replacing evidence. An unchanged roster avoids writes. This tracks units observed since installation; discovering preexisting orphan records belongs to migration/import policy.

The composition root currently supplies an empty task-definition registry because production task behaviors are not yet registered. Unknown task kinds fail validation rather than being discarded. Future behavior registration must supply the same definitions to execution and maintenance. Unit integration tests clear a real queued task using injected definitions; the production-engine death fixture uses an empty valid queue and verifies claims/roster cleanup.

Validation: npm run quality passed (58 production files, zero Lizard violations), npm test passed 175 tests in 2.33s, npm run check:bundle passed, and npm run test:engine:suite passed 11 scenarios in 9.58s. The death fixture invokes production main, issues suicide in its disposable world, then observes claim counts 2→1→1, no remaining roster entry, an empty task queue, and the unrelated claim intact. Unit tests cover serialization reset, replacement IDs, migration-independent bounded cleanup, interrupted checkpoint replay, invalid rosters, and preserved mission state. This is local lifecycle evidence, not full mission/colony/power-creep parity.

# Startup project return policy

ED-29 remains In Progress. The portable `startup/assessment.ts` policy evaluates a completed finite project separately from the simulator and physical resource owners. The persistent planning owner exposes read-only `assess(query, policy)`, reusing its exact input/context/generation/observation/clock matching and completion checks. Absent, incomplete or stale forecasts return no assessment. Policy changes do not rewrite or rerun the forecast. No namespace or schema changes.

The policy explicitly supplies minimum source-delivered energy, minimum final construction-recovery margin, maximum first recovery tick and maximum required household capital. The inclusive horizon is the actual quoted horizon; a deadline beyond it is refused. Household shortfall and required capital use the full household ledger. Delivery, first recovery and final margin use source-only project accounting, so unrelated income can fund workers but cannot establish project return. An earlier recovery crossing is insufficient when final expenses leave a loss. Construction must complete and every requested miner/courier participant must actually have a scheduled birth. Unscheduled unrelated household requests do not become missing source service. Existing paid incumbents are not charged a new birth.

Acceptance is a model-relative decision, never an execution lease, stock reservation or authorization to spawn. The caller must still price complete achievable schedules and relevant risk/authority costs, retain current quote binding and revalidate actual execution through the existing owners. This layer does not invent future workers, reservation renewals, distribution, or income. It supplies neither a universal default nor a new operator configuration switch.

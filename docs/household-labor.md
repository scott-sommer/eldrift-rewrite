# Household labor projection

ED-29 needs paid home workers and their actual energy use in startup economics. The existing outside-spawn cash tag describes a declared bill; it cannot by itself represent carried work energy or prove a native actor consumed it. The portable household/labor module introduces that missing lifecycle boundary with explicit versioning at the forecast persistence boundary. Standalone/full-project integration is described below; broader native calibration and production economic policy adoption remain open.

Each finite job identifies a paid request, action kind, pickup frame, outbound/return travel quote, number of work opportunities and requested load. The worker port supplies an authoritative paid birth plus unboosted body. Birth cost and activation must match that body; missing, inactive, CARRY-less or WORK-less workers cannot withdraw. Lifetimes reuse spawnedActiveTicks, including CLAIM bodies. The model assumes an intact unboosted body and a fixed route quote; changing damage/boosts/routes still needs refusal/requotation at integration.

Withdrawal moves endpoint energy into cargo. Travel occupies the actor without earning income. Work consumes cargo through a separate settled-consumption port; zero means a rejected/unavailable work opportunity, never successful progress. Full unboosted energy limits per WORK per opportunity are build5, repair1, upgrade1, matching pinned processor sources under tools/processors/node_modules/@screeps/engine/src/processor/intents/creeps. Target completion, controller limits and eligibility belong to the consumption adapter, which must return the actual accepted energy, not the offered maximum. No work-progress or source-income credit is inferred here.

The first work opportunity is pickup+1+outboundTicks. The last opportunity or exhausted cargo starts return; deposit starts after another action frame plus returnTicks. Partial deposits retry. A completed return cannot also authorize another pickup by the same body on that frame. Overlapping jobs miss rather than double-booking a worker. Expiry runs before work/deposit and reports actual remaining cargo loss. Conservation per job is picked=cargo+spent+returned+lost. All results and inputs are detached; jobs/frames are bounded. Ports are synchronous trusted effects: exceptions propagate and do not promise rollback of previously accepted effects.

## Funded standalone household integration

Optional household labor now runs in the existing household frame phases. It requires the passive physical model, a matching finite horizon and explicit endpoint capacity. Paid requests and actual admitted births supply worker authority; labor and redistribution request identities must be disjoint. Pickup moves endpoint stock into cargo, work debits outside bank stock only, and returns replenish the endpoint without earning delivery income. Pending external receipts reserve endpoint space before returns, so a current-frame return cannot consume capacity promised to a receipt. The standalone model offers all quoted work opportunities; target eligibility/completion calibration remains outside this forecast.

Build spending is classified as home-construction; repair/upgrade as upkeep. Per-job full-rate consumption compresses to at most two result flows rather than retaining an expense event for every frame. Endpoint expenses cannot spend labor cargo; physical spawn/extension stock remains untouched. TTL loss uses the shared loss owner, once. Checkpoint5 includes labor state while old household1–4 inputs retain their format. Restore cross-checks worker bodies/births against actual spawn admission, full-rate consumption against paid windows, and endpoint, bank, point-stock, cargo, spending and loss totals against each other. Standalone spawn-timeline restore receives the validated construction total so physical/cash checks remain exact.

Full-project labor is explicitly refused until accepting-sink capacity can reserve returns alongside remote deposits and its checkpoint/owner compatibility is qualified. It must not silently accept a labor input while dropping its checkpoint or capacity effects. No current planning/schedule/cache owner claims support for labor yet.

## Full-project accepting-sink integration

Labor is now supported in the full project model. Returns use occupyAfterFrame against the same accepting-sink free capacity used by remote couriers. This internal occupancy does not increment acceptedEnergy or delivery income. Labor pickups release capacity after settlement; work consumption does not release it a second time. Remote acceptance and declared releases settle before labor returns, and pickup space is available only next frame. Endpoint capacity must match the one quoted accepting sink; remote miners/couriers and household labor may not share a paid body.

Project7 retains household5/labor1 checkpoints. Parent links reconcile sink free space with external changes, source deliveries, ordinary pickups, located expenses, labor pickups and labor returns. Both financial ledgers receive actual modeled labor consumption. Planning7, schedule4 and candidate-cache4 now support these inputs. Compatible planning6/schedule3 jobs migrate read-only with progress preserved; cache3 retains recognizable non-labor identities and drops labor/unknown ones before recapture. Older owner versions refuse the new envelopes; older labels may not carry labor metadata. Reset tooling supports the new owner versions while still selecting only derived forecast records.

This supersedes the preceding temporary full-project refusal. The earlier evidence remains scoped to its source. Current qualification and native regression results are recorded separately after clean-source execution; no matched native paid-worker or target-completion evidence is implied by a modeled work window.

MiningStation describes energy/mineral identity, resource position, adjacent access tiles, optional container/link/extractor IDs, throughput, availability, observation/ready times and risk. Validation enforces distinct same-room adjacent tiles. Station metadata is a contract, not yet a persisted observation implementation.

Feature-owned assignments reuse durable exclusive reservations keyed by physical room/tile, rather than station ID: adjacent sources cannot double-book the same standing tile. Claims use caller task scopes so existing task cancellation/death cleanup can release them. Only safe stations accept new leases; unknown/hostile safety handling and retreat belong to behavior policy. Leases expire or release for replacement.

## Continuous miner behavior
minerStep provides a continuous station-work policy through narrow ports: spawning wait, danger-first retreat, explicit missing-target failure, assignment wait, shared movement travel, infrastructure establishment, maintenance, full-store handoff and harvesting. Arrival and accepted work remain running, rather than completing the mining task. Each step selects one work action; a zero-CARRY miner is allowed to harvest without a store.
Energy and mineral readiness are separate functions: energy depletion waits for regeneration; minerals additionally require an active extractor and respect its cooldown. These are observation-driven handlers, not game-global readers. Establishment/handoff mechanics and readiness observations still need native composition; retreat destinations/risk are caller policy.
Validation: 247 tests passed in 2.74s; quality/Lizard passed with 99 production files and zero violations. Tests cover danger priority, unseen versus missing targets, action selection, zero-CARRY handling, depletion, missing extractor and cooldown. No engine station-production evidence yet.

## Native station observations
observeMiningStations reads visible sources/minerals, amounts and regeneration times; energy throughput uses capacity/regeneration time. Risk and mineral throughput are explicit assessment inputs (mineral default zero means no assessed throughput). Access tiles reuse the movement obstacle matrix plus terrain, exclude exit tiles, and ignore transient creep occupancy. Nearby container, owned link and extractor IDs are discovered deterministically. Undefined represents no vision; an empty visible list represents no resources.
Validation: 248 tests passed in 2.66s; quality/Lizard passed with zero violations. New three-tick engine stations scenario verifies source access and adjacent container discovery, validates records and checks unseen-room distinction. Registered in full suite; full suite not rerun this milestone. Infrastructure is station-level discovery; behavior must still check range from its specific assigned tile. Native station production and persistence remain unfinished.

## Durable station knowledge
Feature-owned versioned station records persist per room, with bounded counts, unique station/target identities and observation timestamps. No-vision updates retain knowledge; a visible empty observation removes confirmed missing resources. Reads expose freshness and downgrade stale risk to unknown so stale safe observations cannot authorize new assignments. Availability/ready times remain historical values, not predicted production. Out-of-order, mismatched-room/timestamp, malformed and future-version records fail explicitly.
Validation: 252 tests passed in 2.73s; quality/Lizard passed across 103 production files with zero violations. Serialization/reset, stale assignment rejection, detached snapshots, confirmed removal and corrupt/future state protections are covered. No engine rerun for this persistence-only change. Native behavior composition, production/handoff engine scenarios, throughput saturation, demand integration and main-loop integration remain outstanding.

## Native miner execution
createNativeMiner composes minerStep with shared action ownership and movement services. Live target and extractor observations determine production readiness. Native infrastructure observation filters sinks by actual range, link ownership/activity and resource capacity; it discovers existing adjacent container construction sites and damaged reachable station structures for establishment/maintenance. The caller supplies the reservation result, safety/retreat policy and route policy. This adapter does not allocate population, create construction sites or flush movement independently.
The five-tick packaged mining scenario starts a loaded worker one tile away, reconstructs both services every tick, and verifies travel, harvest to 50 energy, container handoff and resumed harvesting. Exact observed stores: [48,0], [48,0], [50,0], [0,50], [2,50]. No duplicate role-owned pathing is introduced.
Validation: npm run quality passed (105 production files, zero Lizard violations); npm test passed 252 tests in 2.69s; npm run test:engine:suite passed all 23 checks in 19.54s. This proves native energy/container execution with service reconstruction, not complete colony reset recovery.

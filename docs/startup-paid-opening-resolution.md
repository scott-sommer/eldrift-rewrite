# Pending-aware paid courier opening resolution

ED-29 source5b596dc adds a pure opening resolver and native read-only event adapter. It is for a BEFORE-DISPATCH boundary: actual preceding-frame effects are already reflected in native source/container/cargo/home stock, while existing task/journal owners may still owe receipt posting and acknowledgement. The resolver verifies the pending outcome using the existing confirmTransfer native event semantics, or preserves an already-observed persisted journal result. Same-frame intents, missing/wrong-window evidence, cargo deltas that disagree with the effect, conflicting posted receipts and unsupported leftover task cargo defer. Nothing is acknowledged, settled, credited or repaired through owner APIs.

Paid courier task observations now retain actual receipt identities as well as remaining quantity. A pending transfer's continuation subtracts only an as-yet-unposted amount; if its exact receipt already exists, it does not subtract again. Original observation/task/journal data stays copied and unchanged. Verified past effects explicitly carry projectedIncome0: they are part of opening physical stock, not future project receipts or recovery profit. Successful withdrawals may resume loaded movement in the current frame. Completed delivery tasks retain their completion frame before another approach. Partial delivery and actual task wake clocks preserve remaining work without an invented full turnaround.

This is an opening-state translation boundary, not financial permission or a new accounting owner. It does not resolve future SDK results, ignore outstanding claims, or replay an accepted intent. Existing owners still release/rebook claims and post/acknowledge effects normally. Caller ordering is essential: ordinary movement intents are not available from the public native API, so this adapter must run before actor dispatch. Same-frame transfer intents are refused explicitly, but that is not a substitute for the before-dispatch contract. Initial physical trip/project input and native route execution remain unconnected.
